# 兜兜 (doudou)

家庭财务安全 Agent。Autosize OS / OctoSense 上的 Agentic App。

> **通用对话 AI 回答你的问题。**
> **兜兜记住你的生活，并一直帮你看着：这条路，还兜不兜得住。**

GOSIM Shenzhen 2026 Agentic App 黑客松参赛作品 · 财经 / 消费管理场景

---

## 与官方评审标准的对应

官方"最佳 Agentic 奖"三条核心维度 + 平台设计原则，兜兜一一对应：

| 评审维度 | 兜兜怎么兑现 |
|---|---|
| **任务完成**：从真实输入到执行与结果核验 | 用户说一句话 → 自然语言解析 → 写入 `state.json` → 数字由程序按公式算出 → 月数渲染到屏幕 → 用户选择 → 状态变更 → 持久化。**端到端闭环，不是"生成一张界面"** |
| **可靠运行**：状态变化、失败恢复、重复测试 | `state.json` 持久化（关掉再开还在）；数字冲突时指出冲突并**保留已保存状态**（不覆盖）；重置后还能继续推演 |
| **人机协作**：来源可查、授权清楚、操作有反馈 | 数据全部来自用户口述和本机存储（来源可查）；manifest 只申请 storage（授权清楚）；每次按钮点击都有 prompt 反馈；用户能"先不辞，回到现在"（能调整与接管） |
| **主动，而非被动**（平台原则） | 缓冲低于自己设的底线时自己开口；缓冲被明显削薄（即使仍在底线之上）也主动提醒"这件事让安全空间变薄了多少" |
| **人在回路**（平台原则） | **不替你决定**——把三条退路摆出来让你选；不替用户判断该不该买车 / 辞职 / 生孩子 |

下面这段对话演示的就是上面这一整条路径。

## 它是什么

兜兜不是一个 AI 理财助手，不是一个记账 APP，也不是一个家庭财务评分器。

它是一个**持续运行的家庭财务安全系统**：

- 它**记得**你的家庭——收入、家庭成员、房贷、存款、你的安全线、你最担心的事
- 它**理解**你的"兜"——这 80 万对你这个家意味着 29.6 个月的安全缓冲，不是 80 万这个数字本身
- 它**模拟**你想做的事情——买车、辞职、装修、生孩子，会把缓冲从多少变成多少
- 它**盯着**你的底线——状态一旦接近你设的安全线，它自己开口
- 它**留下**你的决定——你上次怎么选的、你为什么选了，下次它还记得

兜兜只回答一个问题：**"我们家，还兜不兜得住？"**

---

## 它不是什么

- ❌ 不是 AI 记账（不替你记每一笔）
- ❌ 不是理财顾问（不推荐基金、股票、保险产品）
- ❌ 不是财务健康评分器（不打分，不评级）
- ❌ 不是银行 / 券商 APP（不连账户、不访问网络）
- ❌ 不是聊天机器人（不陪你闲聊）
- ❌ 不是通用大模型套壳（不假装自己有更聪明的大脑）

兜兜不替你判断该不该买车、该不该辞职、该不该生孩子。**它只告诉你变化。**

---

## 设计哲学（四条红线）

这四条决定兜兜不做什么，比决定它做什么更重要：

1. **不评价你。** "这件事值不值得做？"——不判断。
2. **不替你决定。** "该不该做？"——不说。
3. **只告诉你变化。** "这件事会让你的安全缓冲从 29.6 个月变成 18.5 个月。"说完就停。
4. **记住你的选择。** 你上次说"先不买车"，它下次还会记得，并基于这个继续帮你看。

## 兜兜和通用对话 AI 到底有什么不同

这是比赛里必须讲清的一件事——评审看到的所有"对话式 AI 助手"都能做单次财务分析。

**第一轮对话，兜兜完全没理由认为自己比一个通用对话 AI 强。**
你说一句"我今年 42，月薪 4 万，房贷 1.5 万，存款 80 万，最近想辞职"，通用对话 AI 也能给你一份像样的财务分析。

真正的区别发生在**第十次对话**。

| 维度 | 通用对话 AI | 兜兜 |
|---|---|---|
| AI 对话 | ✅ | ✅ |
| 财务分析 | ✅ | ✅ |
| 情景推演 | ✅ | ✅ |
| **你的家庭状态** | 每次重新理解 | **持续维护** |
| **长期记忆** | 受限于 context | **结构化保存** |
| **你的"兜"是什么意思** | 没专门模型 | **核心模型** |
| 风险变化 | 用户主动问 | **持续监测** |
| 用户做决定以后 | 对话结束 | **继续观察结果** |
| **换模型以后** | 一切归零 | **你的兜还在** |

兜兜不是一个"更聪明的 AI"，而是一个**长期保存着你家庭财务状态的系统**。

**今天用 Kimi，明天用 Claude，后天用 GPT——但是你的兜还在。**

这是兜兜真正的护城河。

## 兜兜能跑通的一整条路（Agent Loop）

这是兜兜真正完整的体验，不是单次对话：

```
用户说："我想买辆 30 万的车。"

        ↓ ① 理解我的家庭
读取 state.json：收入 4 万、房贷 1.5 万、存款 80 万、
安全线 12 个月、最担心失业、家庭一份收入。

        ↓ ② 重新计算
现金：80万 → 50万
缓冲：29.6个月 → 18.5个月
减少：11.1个月

        ↓ ③ 看见变化
车买得起。
缓冲还在 12 个月以上。
但一次削薄 11.1 个月。

        ↓ ④ 判断有没有伤到我的安全边界
尚未跌破 12 个月底线。
但是：缓冲明显变薄 + 单收入 + 用户自己说最怕失业。
= 已经值得主动提醒。

        ↓ ⑤ 主动提醒
兜兜自己开口（不是用户问才出现）：
"我帮你看了一下——"
"这辆车买得起，但它会一次减少 11.1 个月的安全缓冲。"
"你家只有一份收入，而你担心的是失业。"
"所以我不是担心你'买不起'，"
"我更在意你买完以后还剩多少退路。"

        ↓ ⑥ 给出三条退路
🛟 先留着 30 万 → 缓冲回到 29.6 个月
🛟 买，但先看看失业后的时间 → 大约 6.5 个月后触碰底线
🛟 等家里有第二份收入再买 → 安全线不变

        ↓ ⑦ 用户选一条
"先留着。"

        ↓ ⑧ 状态被改变
state.json 写入决策记录：
{ event: "买30万汽车", choice: "先留着", time: ... }

        ↓ ⑨ 下次它还记得
一个月后用户再次说："我还是想买那辆车。"
兜兜不会重新问一遍。
它会说：
"上次你考虑这辆车时，选择先留现金。"
"这次和上次有什么不同吗？"
```

这就是兜兜和计算器之间最大的区别。

## 五层架构：Memory / Model / Simulation / Monitor / Action

兜兜内部不是"AI + 数据库"。它是五层紧密耦合的闭环：

### ① Memory — 记住你

事实和偏好。

```text
家庭
├── 收入（来源数、月金额）
├── 支出（房贷、必要生活费）
├── 资产（可动用现金）
├── 家庭成员（配偶、子女、父母）
├── 安全线（你给自己留的底）
└── 最大担忧（你最怕什么）
```

存在本机 `state.json`，不访问网络。

### ② Model — 理解你的"兜"

兜兜不是存"存款 = 80 万"这个数字。

它知道的是：

```
80 万现金
   ↓ ÷ 必要月支出 2.7 万
   ↓ = 29.6 个月
   ↓ - 你设的底线 12 个月
   ↓ = 余量 17.6 个月
```

**"80 万"对兜兜没有意义，"29.6 个月 + 17.6 个月余量"才是它维护的模型。**

### ③ Simulation — 看未来

任何一件生活里的大事，都通过同一个 Scenario Engine：

- 买车 30 万 → 缓冲从多少变多少
- 辞职休息 6 个月 → 缓冲从多少变多少
- 装修 20 万 → 缓冲从多少变多少
- 收入中断 18 个月 → 缓冲从多少变多少

以后新增事件，不需要给每个事件写一套完全不同的逻辑。

### ④ Monitor — 持续观察

App 打开时，兜兜会重新读 state.json 重新算。

不是只显示上次的数字。

它会看：

- 缓冲有没有接近 / 跌破你设的底线
- 有没有单收入 + 大额支出的组合
- 有没有同时触发多个风险信号

App 里计算，但**当前比赛版本的 OctoSense Shell 还在过渡期，`glance.publish` / `background` 这些"系统级持续观察"能力还属于规划中**——这一版我们用 App 内重算的方式实现产品体验，等平台能力落地再平滑升级。

### ⑤ Action — 主动发现 + 三条退路

兜兜真正"Agentic"的地方不在于"会聊天"。

而在于：

- **看见数字 → 判断是否值得提醒 → 自己开口**
- **每一次选择都留在轨迹里 → 下次还能接上**

三条退路永远是：

1. **先保留现金** —— 缓冲回到当前
2. **先看看最坏情况** —— 模拟某个极端事件
3. **等条件变化** —— 推迟决定，等家庭状态改变

兜兜不替你选。它只把三条摊开。

## 关键技术原则：Collection is code，judgement is the model

这是 OctoSense 官方明确强调的架构原则：

> **数据收集 / 数字计算 = 代码。**
> **意图理解 / 表达判断 = 模型。**

所以兜兜内部是这样分工的：

```
"我想买辆 30 万的车，孩子明年还要上学，我又有点担心失业。"

              ↓ AI 理解层

{
  "event": "purchase",
  "item": "car",
  "amount": 300000,
  "concerns": ["job_loss", "children_education"],
  "time": "near_future"
}

              ↓ 确定性代码（数字由程序算，不由 LLM 编）

存款 80万 - 30万 = 50万
50万 ÷ 2.7万 = 18.5 个月
距离 12 个月底线：6.5 个月余量

              ↓ Agent 判断（要不要提醒、怎么表达 trade-off）

"我帮你看了一下——"
"这辆车买得起，但它会一次减少 11.1 个月的安全缓冲。"
```

**数学永远由代码算。模型只负责听懂 + 表达判断。**

这条原则决定了兜兜绝不会"因为 LLM 算错数字"而出错。

## 为什么不是"又一个家庭理财 App"

中国市场已经有 Grobit、ReFi 算账等产品，在做完整家庭财务管理（资产负债表、五维健康、AI 报告、目标、行动追踪、情景模拟）。

海外已经有 Monarch Money（Forecasting）、Origin（Proactive AI Advisor）、Copilot Money（Money Assistant）。

**如果兜兜去做"一个功能少一点的 Monarch / Origin / Grobit"，没有意义。**

兜兜选择的位置是别人都没占住的：

> **中国家庭语境 + 安全余量 + 生活变化 + 决策记忆 + 主动守望。**

这五样东西连起来，是一个有完整心智模型的 Agentic App，而不是一个缩水版的理财工具。

而且有一个反直觉的设计：**兜兜甚至欢迎用户把通用对话 AI / 银行经理 / 理财顾问的建议拿过来问它。**

> 用户："通用对话 AI 说我可以拿 30 万创业。"
>
> 兜兜："这条建议本身没问题。但放到你的家庭模型里——你拿出这 30 万，安全缓冲从 15 个月降到 7.8 个月。如果你坚持安全线 12 个月，你现在还差 16 万。所以你不是不能创业，而是现在创业需要另外一个兜底方案。"

兜兜不和通用大模型比聪明。它做的是**把你的家庭模型当作通用大模型没有的纵深**。

## 现在已经做了什么（诚实清单）

这版代码在 `bundle/main.splash`，**已经在 OctoSense Shell 里跑过**。

### 已经能做

- ✅ **听懂一句家庭情况**——月薪、房贷、存款、安全线、最担心的事，从一句话里解析出来
- ✅ **写入本机 `state.json`**——重启后状态还在
- ✅ **算当前安全缓冲**——可动用现金 ÷ 必要月支出
- ✅ **算安全余量**——缓冲 - 你设的底线
- ✅ **生活费兜底估算**——用户没说时按 1.2 万估算，并明确标注"是兜兜估算的，可以改"
- ✅ **三件大事推演**——买车 / 休息 6 个月 / 休息 18 个月，同一个缓冲公式重算
- ✅ **跌破底线的告警**——缓冲低于自己设的线，自己开口说"这条路有风险"
- ✅ **"先不辞，回到现在"的退路**——一键回到原状态
- ✅ **决策轨迹**——"我记得你做过这些决定"，关掉再打开还在
- ✅ **数据只在本机**——只用 `fs.*` 写 `state.json`，不访问网络

### 算式（由代码算，不由模型算）

```
可动用现金      = 存款
家庭必要月支出  = 房贷 + 生活费
安全缓冲月数    = 可动用现金 ÷ 家庭必要月支出
安全余量        = 安全缓冲月数 - 你设的底线
```

### 演示家庭

42 岁，已婚，一孩。月收入 4 万，房贷 1.5 万，存款 80 万，配偶暂无收入。最担心失业，希望家里至少撑 12 个月。

按这套数字：
- 现在：29.6 个月
- 买车 30 万后：18.5 个月（少 11.1，距离底线 6.5 个月）
- 休息 18 个月且收入变 0：11.6 个月（**低于底线**）

## 接下来要做（按优先级）

### P0 — 把"兜住体验"做完整

- **重做"我现在"视觉中心**——29.6 个月大数 + 12 个月安全线 + 17.6 个月余量，一眼看见"我家现在稳不稳"
- **买车后展示完整变化链**——80万 → 50万 → 29.6 → 18.5 → 少 11.1 → 离底线 6.5
- **真正落地"怎么兜"三条退路**——三个按钮接上现有函数：先留着 / 看看失业后的时间 / 等第二份收入
- **加入主动触发规则**——即使仍 >12，只要"缓冲明显削薄 + 单收入 + 用户明确担忧"，兜兜自己开口
- **把记忆从日志升级成决定历史**——"上次你选择先留现金。这次和上次有什么不同？"
- **生活费 1.2 万做透明假设 UI**——加"改一下"入口，让用户说出真实数字后重算

### P1 — 完整家庭画像 + 场景扩展

- 完整家庭成员结构
- 每月净结余（开始同时拥有存量安全和流量安全）
- 更多生活事件：装修 / 旅行 / 买房 / 婚礼 / 支持家人 / 收入下降
- 统一事件模型：所有事件都进同一个 Scenario Engine

### P2 — 接住 OctoSense 真正可用的 Agent 能力（等平台开放时）

**当前现实限制**：OctoSense 当前比赛环境还处于"agent 能力从设计到落地"的过渡期。

| 能力 | 当前状态 | 兜兜的策略 |
|---|---|---|
| `fs.*` | ✅ 完全可用 | 本版已用 |
| `Timer` | ✅ 完全可用 | 本版轻量用：App 打开重算 |
| `model.complete` | ⚠️ 可用但有限（只读、无 tools、无 memory、无 conversation history） | 比赛版暂不接入，先把骨架做扎实 |
| `octos.*` (turn/session/history) | ⚠️ 需要 contained apps policy 开启 + 用户授权 | 比赛版暂不依赖 |
| App 自己的 `AGENT.md` / `tools.json` / `skills` | ❌ App Hub 已能 gate，但当前 Shell pin 在旧 App Hub，可能拒绝新字段 | **不硬塞**，避免 App 被旧 Shell 拒绝 |
| `glance.publish` | ❌ 当前 contained store app 还不能直接发布 | 设计好接口，等平台开放 |

我们的态度：**先把产品骨架搭扎实。等平台把 agent / glance / background 真正落到运行时，再一行一行接进来。**

我们不为了"看起来 Agentic"而塞当前还不能跑的字段。

### P3 — 主动守望 + Memory 真正长出来

- 家庭状态发生显著变化 → 兜兜主动开口
- 接近底线 → 提前提醒，不等跌破
- 用户关注的风险发生变化 → 重新评估
- 长期 Decision Memory——跨周、跨月、跨年地记住你的轨迹

| 组件 | 作用 |
