# 架构（ARCHITECTURE）

兜兜是跑在 OctoSense 平台上的 OctoScript/Makepad 卡片应用。核心原则一句话：

> **AI 负责听懂一句话，确定性引擎负责算数，用户负责确认。**

模型永远不能绕过校验和确认直接产生财务结果。

## 数据流

```
家庭状态(state.json)                    事件(events.json)
      │                                      ▲
      │ ①读取基线                            │ ⑤确认后持久化
      ▼                                      │
┌─────────────┐   ②自然语言/手动表单   ┌──────────────┐
│ 家庭状态层   │◄──────────────────────│  事件输入层   │
└─────────────┘                        └──────┬───────┘
                                              │ ③校验(类型/枚举/范围)
                                              ▼
                                       ┌──────────────┐
                              用户确认→│ 校验与确认层  │
                                       └──────┬───────┘
                                              │ ④仅已确认事件
                                              ▼
                                       ┌──────────────┐
                  ⑥基线 vs 情景对比 ◄──│ G3 确定性计算 │
                                       └──────────────┘
```

## 1. 家庭财务状态层

保存模拟基线：月收入、房贷、必要生活费、可动用现金、安全底线月数、最担忧的事。存本机 `state.json`（storage jail 内），不访问网络。重启时重新读取并重算。

## 2. 事件输入层

两条入口，产出同一种结构化事件草稿（类型、金额、持续月数、发生月份、名称）：

- **手动表单**：选类型 → 顶部输入框填数字 → 点对应字段按钮。月份为 1-based（第 1 月 = 1），输入映射层转 0-based 存储。
- **AI 草稿（v0.3.2 起，候选）**：一句话 → `host.request("model.complete", {task, input:{utterance}, schema, class:"fast"}, …)` 一次调用 → 应用侧 schema 校验（eventType 七类枚举、startMonth 1–601、duration 0–600、金额 ≤1 亿）→ 仅填充表单草稿。模型返回全 null 金额时确认阶段被拦截。AI 草稿确认后带 `source="ai_confirmed"`。

## 3. 校验与确认层

`ev_confirm → ev_validate → ev_map`：非零金额校验、事件类型白名单、引擎映射。**用户确认前，AI 草稿不写入事件列表、不执行 G3、不持久化**；确认是唯一入口（`确认并计算` 按钮）。

## 4. 确定性计算层（G3）

G3 用已确认的结构化输入计算逐月现金路径：现金 + 各月净结余累积 + 一次性支出（按发生月扣一次）。输出期末现金、安全缓冲月数、与底线的距离、逐月条形图数据。**任何模型输出都不进入这一层**。另有独立的手算证据页（`ev_evidence`，不调用 g3、不读引擎结果，独立算术供用户复核，两个路径数字一致时互证）。

## 5. 持久化与结果展示层

确认后的事件写入 `events.json`（同 id 替换 = 原地更新），重启后恢复进列表（加载时做整数/范围校验，越界与未知类型跳过）。结果页对比基线与情景：缓冲从多少到多少、离底线多远；跌破底线时主动告警；决策（先留着/等一等/做下去）写入决策记忆，重启仍在。

## 6. AI 接入与失败降级

- 调用契约：平台托管的 `host.request("model.complete", …)`，一次调用、不循环、不重试、不伪造。能力声明在 manifest（`capabilities: ["storage","model"]`），Provider 与密钥由平台宿主保管，应用不见任何密钥。
- **每次调用带序号**；回调校验「仍在事件编辑页 + 序号一致 + 仍在等待」三者成立才应用草稿，否则丢弃——迟到响应不覆盖用户手动编辑。等待期间手动编辑会作废在飞调用。
- **本地 60 秒超时**：宿主回调挂死时转为诚实错误。等待期防重复点击；`host.request` 同步抛错也有兜底。
- 降级矩阵覆盖：宿主无 model 服务（`no service answers "model" on this device`）、未授予能力、no_provider、预算/限流、输出不合法、超长输入、请求被拒——全部给出中文提示并保留手动路径；**无模型服务时全部财务功能照常可用**。

## 7. 验证与限制

- 已验证（真实执行）：编译与 `hub check` PASSED；card-host 真实点击回归（建档/降级文案/1-based 月份/53.9 万计算/重启恢复）；Node 126/126。
- 平台范围：交互在 macOS（Apple silicon）的 card-host 上验证；真机 / OctoSense Shell 暂未覆盖。
- AI 辅助事件结构化：模型输出仅作草稿，经 schema 校验与用户确认后执行确定性计算；宿主无模型服务时自动降级为手动填写，全部财务功能照常可用。
